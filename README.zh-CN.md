# Kaggriculture 中文规则

一个双人农场模拟游戏：玩家通过种植、养殖和动态市场交易来最大化收入。

## 游戏概览

每名玩家从一座空农场和一笔启动资金开始。每回合可以移动、购买种子或牲畜、播种、浇水、收获农产品或动物产品，并将产品卖给市场。游戏运行固定长度的一季，最终银行余额较高的玩家获胜。

## 对象类型

| :---- | :---- | :---- | :---- | :---- | :---- | :---- | :---- | :---- | :---- |

| **胡萝卜 CARROT** | 一次性 | 20 | 35 | 2 天 | 3 天 | 无 | 4 | 1 | 1.333 |
| **番茄 TOMATO** | 持续产出 | 50 | 60 | 8 天 | 不适用 | 每天 | 4 | 1 | 4 |
| **草莓 STRAWBERRY** | 持续产出 | 100 | 120 | 10 天 | 不适用 | 每两天 | 4 | 1 | 2 |
| **西瓜 MELON** | 一次性 | 80 | 250 | 10 天 | 12 天 | 无 | 6 | 1 | 0.5 |
| **鹅/蛋 GOOSE/EGG** | 持续产出 | 300 | 50 | 4 天 | 不适用 | 每天 | 4 | 1 + 1（建鸡舍） | 2 |

所有植物都必须每天浇水。所有动物都必须每天使用小麦喂食。如果连续两天没有照料，植物会变成杂草，动物会逃跑且无法找回。小麦也可以在市场上购买，购买价格为当前市场价。

## 动作

每回合玩家可以执行一个动作。每天 24 回合，一季 30 天，共 720 回合。

### 农夫/农场工人动作

每个农夫或工人每回合都可以被分配一个动作。农夫和工人可以占据同一个格子。

#### 移动

- `NORTH`：向北移动一格
- `SOUTH`：向南移动一格
- `EAST`：向东移动一格
- `WEST`：向西移动一格

#### 仓库

拾取物品时必须站在仓库的正交相邻格（上、下、左、右）。

- `PICKUP <item> [n]`：从仓库取最多 `n` 个 `<item>` 到当前农夫/工人的随身库存；默认取 1 个。仓库中的任何物品都可以取，包括动物、肥料和收获物。种子位于独立槽位中，不会被拾取，`PLANT` 会直接消耗种子。
- `DROP`：站在仓库正交相邻格时，将当前单位的全部随身库存倒入仓库。仓库超出容量的部分会被丢弃；不在仓库旁时无效。

#### 植物

- `PLANT`：使用市场购买的种子播种。
  - 所有农夫和工人共享种子库存。
  - 如果同一回合多个单位试图种植超过现有数量的某种种子，则这一种植操作全部失败。例如只有 1 个西瓜种子，却有两个单位同时执行 `PLANT MELON`，则都不会成功。
- `WATER`：给当前格子的植物浇水。每天只需要成功浇水一次，同一天的后续浇水无效。
- `HARVEST`：从植物上收获农产品。没有后续产出的植物会在收获后从地图上移除。每次收获至少得到 1 个单位，额外产量由浇水和肥料决定，具体公式见“收获产量”。
- `FERTILIZE`：给植物施肥，提高潜在产量。
  - 肥料会使接下来 3 天的每日产量加成翻倍。
  - 只有在当天同时浇水时，肥料加成才会生效。

#### 动物

- `PLACE <item> [n]`：将当前单位库存中的物品放置到结构或仓库中。
  - **放置动物**：站在匹配且未占用的结构上，将一个动物放到该结构中。鹅必须放入鸡舍；羊和牛必须放入牧场。参数 `n` 会被忽略。
  - **放入仓库**：站在仓库正交相邻格时，将最多 `n` 个 `<item>` 从随身库存放入仓库；默认 1 个。仓库容量不足时，超出部分仍留在随身库存中。
- `FEED`：使用小麦喂动物。每天只需要成功喂食一次。
- `HARVEST`：收集动物产出的蛋、牛奶或羊毛。
- `COLLECT_FERTILIZER`：从动物处收集 1 个肥料。每只存活动物在每天结束时产生 1 个可收集肥料；收集后消耗当天的库存，下一份肥料要等下一次日终刷新产生。
- `CARE`：照料动物，每天最多一次；当天重复照料无效。具体照料奖励见下文。

#### 动物照料

如果动物当天既喂食又被照料，则在日终时将产量奖励存入 `pending_care_bonus`，增加 2 点。

- 在动物下一次计划产出的当天，如果动物已喂食，所有已积累的奖励都会加入这次产量，基础产量为 1，之后奖励清零。
- 如果动物在计划产出日没有喂食，当天不会产出，已积累奖励也会清零。
- `pending_care_bonus` 受到每只动物 `max_held` 产量上限的间接限制。

#### 地形

- `BUILD_COOP`：在未占用格子上建造一个鸡舍。
- `BUILD_PASTURE`：在未占用格子上建造一个牧场。
- `DIG`：移除当前格子的植物、杂草、鸡舍或牧场。移除植物或建筑不会返还资源；清除杂草也不会产生农产品。

#### 其他

- `PASS`：跳过本回合；没有其他事情可做时可以使用。

### 市场动作

每回合最多可以提交 `maxMarketOrdersPerTurn` 个市场动作，默认上限为 10。超过上限的订单会被静默丢弃。市场订单按顺序排列，但双方订单会以并行的方式处理：当双方都有订单时，每次各处理双方当前订单的一个单位。

- `BUY_SEED <crop> <n>`：购买 `n` 个某种作物的种子。
  - 示例：`BUY_SEED WHEAT 1`
- `BUY_ANIMAL <animal> <n>`：购买 `n` 只动物。
  - 示例：`BUY_ANIMAL GOOSE 1`
- `BUY_PRODUCT <item> <n>`：购买市场产品。
  - 示例：`BUY_PRODUCT WHEAT 1`
  - 示例：`BUY_PRODUCT FERTILIZER 1`
- `SELL <item> <n>`：向市场出售 `n` 个物品。
  - 示例：`SELL WHEAT 1`
- `HIRE`：当天雇佣一名农场工人。当天雇佣越多，费用越高。
- `BUY_LAND`：购买并解锁一个新的土地区域。

## 智能体动作返回格式

智能体函数每回合返回一个动作字典：

```python
{
  "farmer": [op, ...args],          # 主农夫本回合的一个动作
  "hands":  [[op, ...args], ...],   # 按工人顺序，每名工人一个动作
  "market": [[op, ...args], ...],   # 按顺序排列的市场订单
}
```

非法动作会被静默视为无效操作，不会报错。`market` 列表每回合最多处理 `maxMarketOrdersPerTurn` 个订单。

## 浇水和喂食

植物和动物至少需要每隔一天被浇水/喂食一次。浇水每天只需一次，同一天的后续浇水无效。

如果植物连续两天没有浇水，日终时会变成杂草；如果动物连续两天没有喂食，日终时会逃跑且无法恢复。

注意：在一次性作物的产出窗口内浇水，可以提高最终产量；持续产出植物和动物不使用这种累计浇水加成。

## 收获产量

植物的产量会根据照料情况提高。

### 一次性作物

一次性作物包括小麦、胡萝卜和西瓜。从该植物“达到最大产量日”的一半开始，并向上取整，进入浇水加成窗口。在窗口内浇水，每天会给最终可收获总量增加 1 个单位。

施肥植物每天增加 2 个单位，而不是 1 个单位。

例如西瓜达到最大产量的时间是第 12 天，因此从第 6 天开始进入加成窗口。

### 持续产出作物

持续产出作物包括番茄和草莓。每次计划产出的基础产量为 1。如果该植物在产出当天同时施肥并浇水，则该次产量翻倍为 2。

### 衰减

植物达到最大寿命后，其当前可产出数量每隔一个回合减少 1，直到降为 0；降为 0 后植物变成杂草。

- 一次性作物在 `max_yield_day` 之后的一天达到最大寿命。
- 持续产出作物在累计产出次数达到 `max_yield` 后的一天开始衰减。累计产出次数按实际触发的计划产出计算，不论之前是否已经收获。

## 地图特征

每名玩家有自己的农场，其他玩家可以看到农场状态，但看不到对方仓库的私有状态。

### 农场空间

每座农场是一个 `boardSize × boardSize` 的网格，默认大小为 10×10，划分为四个 5×5 象限。开始时只拥有西北象限（NW），其余区域需要购买。

土地解锁费用逐渐增加，依次为：

```text
NE：1000
SW：2000
SE：4000
```

每株植物或每个动物结构占用一个格子。玩家可以自由分配格子用于种植和养殖，不限制某种类型的数量。

杂草有概率在农场的空置且已解锁格子上生成，必须先使用 `DIG` 清理，才能再次使用该格子。

格子可能处于以下状态：植物、鸡舍、牧场、杂草或空地。

### 仓库

仓库用于存放已收获但尚未卖出的产品、动物和肥料。种子位于独立的种子库存中，不占用仓库容量。

每天开始时，主农夫和当天雇佣的工人会在仓库附近生成。每天结束时，所有单位的随身库存会自动放入仓库（前提是仓库有空间）。

仓库最多存放 100 个非种子物品。仓库装满后，之后通过 `PLACE` 或日终自动放入的物品会被丢弃，没有额外的溢出库存。因此，把物品暂时放在农夫或工人身上不能真正绕过仓库上限。

### 农夫和农场工人

#### 雇佣

雇佣是一个市场订单，工人只在当天存在。每天结束时，所有工人会将库存放入仓库并消失；第二天如需继续使用，必须重新雇佣。

同一天的雇佣费用按 Fibonacci 数列增加：

```text
费用 = farmHandCostMult × fib(n)
```

其中 `n` 是当天已经雇佣的工人数，数列从 `1, 1, 2, 3, 5, 8, 13...` 开始。默认 `farmHandCostMult = 1`，因此当天雇佣费用为：

```text
1, 1, 2, 3, 5, 8, 13, 21, ...
```

每天会在仓库正交相邻的空闲位置按 NWSE 顺序生成工人。如果没有空闲位置，会选择占用人数最少的位置，并继续使用 NWSE 顺序打破平局。

#### 随身库存

农夫或工人收获、拾取的物品会进入其随身库存。可以将物品放入仓库。

日终时，所有单位的库存都会尝试放入仓库；如果仓库剩余空间不足，超出的物品会被丢弃。库存溢出不会保留到下一天。

## 城镇建筑

赛季进行期间，城镇会按固定间隔解锁新商店，默认每 3 天解锁一个。每次从尚未解锁的商店池中随机选择一个；一旦解锁，在本局剩余时间内始终有效。

随着商店数量增加，总需求只会增加，不会减少。

每个已解锁商店默认每 4 回合消耗一次它需求的每种产品。单一产品商店会消耗 2 倍数量。

因此，一个需求小麦的普通商店在默认设置下每天会从市场消耗 6 个小麦。

此外，城镇中心每 12 回合消耗一次除肥料外的每种产品：

- 第 0–10 天：每种消耗 1 个；
- 第 11–20 天：每种消耗 2 个；
- 第 21 天以后：每种消耗 4 个。

| 商店 | 增加的需求 |
| :---- | :---- |
| Bakery 面包店 | 蛋、小麦 |
| Pizza Shop 披萨店 | 牛奶、番茄、小麦 |
| Brunch Spot 早午餐店 | 蛋、小麦、草莓 |
| Yarn Store 毛线店 | 羊毛（2 倍） |
| Ice Cream Shop 冰淇淋店 | 草莓、牛奶、小麦 |
| Pet Cafe 宠物咖啡馆 | 胡萝卜（2 倍） |
| Smoothie Shop 果昔店 | 草莓、牛奶 |
| Farmers Market 农夫市场 | 小麦、胡萝卜、番茄、草莓 |

## 市场机制

种子和动物有无限供应，购买价格固定。产品的出售价格会动态变化，并且会跨天持续。

所有产品和肥料在游戏开始时的市场库存都是 `I0 = 10,000`，远高于一局游戏中通常能够生产的数量，因此库存通常会保持为正数。

### 玩家向市场出售

玩家可以在一个市场动作列表中提交任意数量的买入或卖出订单。订单会同时在双方之间按单位处理。

例如，当双方都首先提交 `SELL CARROT 10` 时：

1. 双方的第一个胡萝卜都按当前胡萝卜价格出售；
2. 两个胡萝卜加入市场库存；
3. 市场价格可能因此变化；
4. 然后继续处理双方的下一个胡萝卜。

如果出售价格已经降到 `$1`，该产品仍会被市场买走，但不会再加入市场库存，从而使价格底部对后续买入保持响应。

### 玩家从市场购买

玩家只能通过 `BUY_PRODUCT` 购买小麦和肥料，其他产品只能出售，不能买回。

两种行为会消耗市场库存：

- 城镇中心和商店的自动消耗；
- 玩家的 `BUY_PRODUCT` 订单。

买入订单也会按照双方订单并行、逐单位处理。如果玩家在订单执行过程中现金不足，该订单会停止。

买入价格按买入后的市场库存报价；卖出价格按卖出前的市场库存报价。因此，在其他条件不变时，对同一种产品立即买入再卖出，净收益正好为 0。

### 价格函数

每种资源的价格曲线由基础价格、锚定吞吐量 `T` 以及平衡点两侧各自独立的形状函数和目标变化幅度决定：

```text
price(inv) = base + sign · amp · f(|inv − I0|)

sign = +1，当 inv < I0（稀缺，价格上涨）
sign = −1，当 inv > I0（过量，价格下跌）
amp  = target · base / f(T)
```

其中形状函数 `f` 可以是：

```text
linear、sq、sqrt、log、log10
```

`log` 使用 `ln(1+x)`，因此 `f(0)=0`。价格最终会向下取 `$1` 的下限，并四舍五入到最近的整数美元。

`T` 是一个 5×5 农田在 24 天内、最佳浇水且不使用肥料时的生产能力。动物的 `T` 已预先打 30% 折扣，以考虑喂养所需的小麦成本。

`target` 表示：当库存偏离 `I0` 达到 `T` 个单位时，价格相对于基础价格移动 `target × base`。

不同资源可以在平衡点两侧使用不同的形状和目标，因此生产能力相近的资源也可能具有完全不同的市场策略。小麦在短缺时价格上涨明显，但更能吸收过量供应；胡萝卜则相反。西瓜对短缺反应较小，却会因过量供应快速崩盘。羊毛类似西瓜，但规模更小。

基础价格超过 100 的高级资源（草莓、西瓜、牛奶、羊毛）使用大于 1 的 `above_target`，因此即使市场出现适度过量，价格也可能直接跌到 `$1`。这类资源更需要集中出售和把握时机。

| 资源 | 基础价 | I0 | T | 低于平衡函数 | 低于目标 | 高于平衡函数 | 高于目标 | P(I0−T) | P(I0+T) | P(I0+2T) |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| **小麦** | 25 | 10,000 | 400 | sqrt | 0.80 | log | 0.20 | 45 | 20 | 19 |
| **胡萝卜** | 35 | 10,000 | 450 | log | 0.20 | sqrt | 0.70 | 42 | 10 | 1 |
| **番茄** | 60 | 10,000 | 200 | linear | 0.40 | sqrt | 0.60 | 84 | 24 | 9 |
| **草莓** | 120 | 10,000 | 100 | sqrt | 0.70 | linear | 1.60 | 204 | 1 | 1 |
| **西瓜** | 250 | 10,000 | 300 | log | 0.20 | sq | 3.60 | 300 | 1 | 1 |
| **蛋** | 50 | 10,000 | 332 | linear | 0.40 | log | 0.20 | 70 | 40 | 39 |
| **牛奶** | 160 | 10,000 | 122 | sqrt | 0.60 | linear | 1.60 | 256 | 1 | 1 |
| **羊毛** | 200 | 10,000 | 105 | log | 0.20 | sq | 3.20 | 240 | 1 | 1 |
| **肥料** | 100 | 10,000 | 200 | linear | 0.40 | linear | 0.40 | 140 | 60 | 20 |

默认参数位于 `kaggriculture.py` 的 `MARKET_PARAMS` 中。创建环境时可以通过 `env.configuration["marketParams"]` 对任意资源覆盖部分参数，例如：

```python
{"WOOL": {"above_target": 0.95}}
```

## 回合处理顺序

每个回合按以下顺序处理：

1. **动作验证**：检查动作是否合法；
2. **玩家动作**：记录双方玩家动作；双方动作同时发生；
3. **市场动作**：按前述规则处理市场订单；
4. **城镇购买动作**：城镇中心和商店减少市场库存；
5. **更新观测**：
   - **日刷新**：如果进入新的一天，刷新植物和动物状态，并将浇水/喂食标记重置为未完成；
   - **市场刷新**：根据上一回合的出售行为更新价格；
   - **收入更新**：根据买卖更新玩家银行余额；
   - **农场更新**：清除已收获植物，处理已使用或已出售的库存，将新植物和动物放到农场上。

## 胜负条件

游戏结束时，银行现金最多的玩家获胜。双方现金相同则平局。

## 得分

最终银行现金最多的玩家获胜。库存中尚未出售的物品不计入最终得分。

## 观测格式

每回合传给智能体的顶层观测如下：

```python
{
  "player": int,              # 当前玩家编号：0 或 1
  "step": int,                # 当前回合，0-based
  "day": int,                 # 游戏内日期，0-based
  "hour": int,                # 当天回合，0..turnsPerDay-1
  "farms": [farm, farm],      # 双方公开农场状态，按玩家编号索引
  "market": {                 # 共享市场状态
    "inventory": {"WHEAT": int, "CARROT": int, ...},
    "prices": {"WHEAT": int, "CARROT": int, ...},
  },
  "town": {                   # 共享城镇状态
    "unlocked_shops": ["BAKERY", ...],
  },
  "private": {                # 仅当前玩家可见
    "shed": {"WHEAT": int, "GOOSE": int, "FERTILIZER": int, ...},
    "seeds": {"WHEAT": int, "CARROT": int, ...},
    "inventories": [farmer_inv, hand_inv, ...],
  },
}
```

每个 `farm` 字典是公开的，双方都能看到：

```python
{
  "money": float,
  "tiles": [[tile, ...], ...],       # 使用 tiles[y][x]
  "farmer": [x, y],
  "hands": [[x, y], ...],            # 当天雇佣的工人
  "unlocked_quadrants": ["NW", ...],# 属于 {"NW", "NE", "SW", "SE"} 的子集
  "hires_today": int,                # 用于计算下一次 HIRE 价格
}
```

一个 `tile` 可能是以下类型之一：

- `None`：空的、已解锁格子；
- `"LOCKED"`：尚未购买象限中的格子；
- 植物字典：

  ```python
  {
    "kind": "PLANT",
    "crop": "WHEAT" | "CARROT" | "TOMATO" | "STRAWBERRY" | "MELON",
    "planted_day": int,
    "watered_today": bool,           # 每天结束时重置为 False
    "consecutive_unwatered": int,    # 达到 2 或以上会变成杂草
    "yield_units": int,               # 当前可收获数量
    "max_lifespan_step": int,         # 开始衰减的 step；持续作物为 -1
    "fertilized_until_day": int,      # 肥料加成适用的最后一天；没有则为 -1
  }
  ```

- 杂草字典：

  ```python
  {"kind": "WEED"}
  ```

- 动物结构字典，可以为空或已放入动物：

  ```python
  {
    "kind": "COOP" | "PASTURE",
    "animal": "GOOSE" | "COW" | "SHEEP" | None, # 放置动物前为 None
    "placed_day": int,
    "yield_units": int,
    "fed_today": bool,
    "consecutive_unfed": int,        # 达到 2 或以上动物会逃跑
    "cared_today": bool,
    "fertilizer_available": bool,    # CARE 后设置；COLLECT_FERTILIZER 后清除
    "pending_care_bonus": int,        # 存储的 CARE 奖励，在下次产出时使用
  }
  ```

## 快速开始

```python
from kaggle_environments import make


def my_agent(obs):
    # 第一回合购买 1 个小麦种子，之后永远跳过。
    if obs.get("step", 0) == 0:
        return {"farmer": ["PASS"], "market": [["BUY_SEED", "WHEAT", 1]]}
    return {"farmer": ["PASS"], "market": []}


env = make("kaggriculture", configuration={"episodeSteps": 200})
env.run([my_agent, "random"])
env.render(mode="ipython", width=800, height=800)
```

## 配置默认值

每种作物的种子成本和每种产品的基础价格不可配置，见上面的对象类型表和价格函数表。可配置参数如下：

| 参数 | 默认值 | 说明 |
| :---- | :---- | :---- |
| `episodeSteps` | 720 | 一季的总回合数，即 24 回合 × 30 天 |
| `boardSize` | 10 | 每名玩家正方形农场的宽度和高度；高级配置中 10×10 会分成四个 5×5 象限 |
| `startingMoney` | 3000 | 每位玩家的初始金币 |
| `maxMarketOrdersPerTurn` | 10 | 每位玩家每回合最多处理的市场订单数；超出的订单静默丢弃 |
| `turnsPerDay` | 24 | 一个游戏日包含的回合数 |
| `shedCapacity` | 100 | 仓库最多存放的非种子物品数量；日终放入时超出部分丢弃 |
| `weedSpawnChance` | 0.005 | 每个已解锁空格在日终刷新时生成杂草的概率 |
| `townShopUnlockInterval` | 3 | 城镇连续解锁商店之间的天数 |
| `townShopSellInterval` | 4 | 每个已解锁商店两次消费之间的回合数 |
| `townCenterSellInterval` | 12 | 城镇中心两次消费之间的回合数 |
| `seed` | `null` | 可选的随机种子，用于生成确定性的对局；读取后会从配置中清除，因此不会出现在智能体观测中 |
